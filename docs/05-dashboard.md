# Etapa 6 — Dashboard

A Dashboard será a principal tela do sistema. Deverá se basear no que foi definido no PRD, porém de forma mais rica e completa. O usuário deve sentir que está olhando para o seu planejamento financeiro e ter uma noção clara de como anda sua vida financeira. Para isso, a dashboard deve priorizar os elementos visuais e interativos, sempre que possível, junto com responsividade priorizando dispositivos móveis. Evitar uso de tabelas, priorizando gráficos e cartões, mas manter a organização em forma de linhas e colunas. 

Exibir no máximo 4 meses simultaneamente em dispositivos móveis, e no máximo 12 meses simultaneamente em dispositivos desktop. Caso exista mais meses disponíveis, o usuário poderá navegar entre os meses utilizando setas para a direita e para a esquerda.  Um mês não se confunde com outro mês de outro ano, salvando e exibindo corretamente. Por exemplo, "Dez25" deve ser um mês diferente de "Dez26".

Implementar:

- visualização horizontal dos meses;
- responsividade priorizando dispositivos móveis.
- visualização dos envelopes de cada mês;
- edição do limite do envelope para um mês específico;
- consumo por envelope no mês;
- saldo geral;
- saldo líquido;
- saldo livre (sem vínculos com envelopes);
- barras de utilização;
- resumo mensal.

Utilizar apenas dados reais do Firestore.

Não utilizar mocks.

Ao finalizar:

- revisar;
- validar;
- apresentar resumo.

Aguardar aprovação.
